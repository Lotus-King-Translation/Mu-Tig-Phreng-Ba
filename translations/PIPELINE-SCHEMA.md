# Strict translation pipeline — v1

Canonical content: `paired/source.md`, `paired/translation.md`, mirrored by per-chapter `translations/chapters/NN/source.md` and `translation.md`. Chapter snapshots are authored inputs; generated reader/machine files are not editorial inputs. Golden and glossary bytes remain unchanged.

Commands: `python scripts/translation_pipeline.py plan|source|seal-audit|assemble|build|validate --chapter N`; validation adds `--source-only` or `--final`. `plan` freezes segmentation and source/glossary/standard identity before English exists. `source` seeds exact Tibetan snapshots and the scoped source prefix. `assemble` copies authored snapshots into the two canonical prefix files. `build` writes only reading.md, bilingual.md, machine.json, coverage.json, build-manifest.json. `validate` is read-only; `--final` requires QC and signoff. Root publishes.

Every Markdown file starts with scalar front matter: `schema: paired-text/2`, `text-id: MTP`, `language: bo|en`, `source-commit`, `source-sha256`, `glossary-sha256`, `standard-sha256`, `scope-first-chapter`, `scope-last-chapter`. Tibetan also has `edition: golden-v1`; English has `source-edition: golden-v1`, `translation-edition: translation-v1`. Snapshot scope is N..N; canonical scope is 1..N. `unset` is invalid.

Source marker: `<!-- pair: ID | golden: SPACE_SEPARATED_IDS | role: ROLE | format: prose|verse|h1|h2|h3 -->`. English marker: `<!-- pair: ID -->`. English never duplicates format. Pair framing uses one blank line after each marker and between pairs; preserve any additional leading source newline (including an initial blank object). Source pair body is exactly the selected golden object strings joined by one newline, without normalization. Separate pairs at substantive source-role or format boundaries. Explicit paired projections are source_metadata ← metadata/blank, source_heading ← heading, source_annotation ← annotation, work_colophon ← colophon. Blank plus metadata may share a source_metadata pair; exact original roles and objects remain in machine.json. Blank/metadata objects still receive IDs. Pair identity may use stable project-defined alphanumeric/hyphen IDs.

The literal `<!-- endnotes -->` ends English pair bodies. All definitions follow as `[^NOTE-ID]: prose`; continuation lines indent four spaces. Inline references remain at their affected pairs. No footnote definitions in pair bodies. Each nonempty note has one definition and at least one local reference.

Authored chapter JSON inputs:
- `segmentation.json`: array `{id,golden_ids:[],role,format,rationale}`; every chapter golden object exactly once, in order. The frozen array defines format boundaries.
- `note-map.json`: array `{id,pair_ids:[],golden_ids:[],category,obligations:[]}`. Categories: `adzom_difference`, `transcript_correction`, `source_omission`, `source_layer`, `uncertain_reading`, `presentation`, `golden_uncertainty`, `translation_issue`, `terminology_provisional`.
- Obligations are exact strings `golden-change:<decisionID>` (all changes including roles), `golden-uncertainty:<anchorID>:<zero-based index>`, `adzom:<audit-findingID>`. All must be covered; audit additions after a draft remain mandatory. Every affected pair references its note. English explanation remains canonical in translation.md, not duplicated in JSON.
- `pair-status.json`: array `{id,status:translated|unresolved|nontranslatable,reason,note_ids:[]}`. Unresolved/nontranslatable substantive pairs require a local endnote and explanation; blank/metadata may instead use an explicit bracketed label plus reason.
- `adzom-audit.json`: root/auditor schema `{chapter,scope,inspector,images:[{image_index,printed_page,path,sha256,anchor_ids,status,unresolved:[]}],anchor_checks:[{anchor_id,status:"agrees|differs|uncertain|metadata|blank",image_indices,findings:[]}],findings:[{id,type,anchor_ids,golden_reading,adzom_reading:null_or_exact_string,explanation,english_consequence,evidence:[{path,sha256,image_index,printed_page,rows_or_crop,allocation_reason}]}],limits}`. Every chapter object occurs once in anchor_checks; all substantive anchors have allocated image evidence. Finding types are `adzom_difference|source_omission|source_layer|uncertain_reading|presentation`. Uncertain/differing checks need findings. Image/evidence hashes and allocation fields are checked; this does not certify the inspector’s reading.
- `usage.json` and `glossary-proposals.json`: optional supporting authored records, hashed when present; semantic QC must explicitly report their availability and any missing required usage documentation. They never change glossary authority. The author’s translation-note-map.json and preserved translation-draft.md are also hash-bound when present; the coordinator merges author notes with source obligations into note-map.json.

`contract.json` plus `contract.sha256` freeze source identity, segmentation hash, exact chapter range, glossary/standard hashes and all obligations known at planning. `seal-audit` validates complete native coverage and writes audit-contract.json plus audit-contract.sha256, binding current audit bytes and obligations before candidate build. Resealing an unsigned candidate can add obligations but cannot remove known ones. Every candidate recomputes current audit obligations; removing known obligations fails. Outputs bind the complete current audit and evidence hashes, so later findings invalidate QC/signoff until rebuilt and reviewed.

Final authored `qc.json`: `{chapter,reviewer,translator,independent:true,source_sha256,translation_sha256,build_manifest_sha256,coverage:"complete",disposition:"ready_for_human_editing"|"ready_with_explicit_review_flags",open_blockers:[],review_path,review_sha256}`. Reviewer must differ from translator. Final `signoff.json`: `{chapter,approved:true,reviewer,build_manifest_sha256,output_sha256,qc_sha256,review_path,review_sha256}`. Review files stay inside the repository. Mechanical validation never certifies semantic accuracy.

Publication receipt: `translations/publication/chNN-v1.json`, with `chapter`, `tag: translate-chNN-v1`, `release_commit`, `remote_tag_object`, `remote_peeled_commit`, `remote_main_at_release`, `build_manifest_sha256`. All prior chapter snapshots/outputs are checked against those annotated tags before starting the next chapter. Their pair bodies and endnotes must remain identical within the growing canonical prefix. Chapter 8 coverage must total all 2,053 golden objects; whole-book `translation-v1` publication remains a separate coordinator gate.

## Complete translation aggregate

`python3 scripts/build_translation_aggregate.py build|verify` requires all eight fixed `translate-chNN-v1` annotated tags and committed publication receipts. It refuses missing chapter snapshots, QC, signoffs or receipts before writing output. `verify` regenerates expected bytes in memory and never writes. `python3 scripts/test_translation_aggregate.py` exercises a synthetic eight-release repository; it does not certify Tibetan readings or English meaning.

Generated whole-book files are `translations/reading.md`, `bilingual.md`, `machine.json`, `coverage.json`, and `build-manifest.json`. Canonical source/English pair text, original golden objects (including roles, layers and uncertainties), note definitions and obligation mappings remain exact. Reader Markdown applies inherited display formatting; every note definition is collected at the end. All 2,053 golden objects must occur once, in their fixed order. Metadata, unresolved and nontranslatable objects remain represented; `source_objects_represented` is explicitly separate from `source_objects_by_pair_treatment` and is not a semantic completion claim.

The aggregate checks every released chapter file and manifest input against its fixed Git tag, including native evidence, source contracts and audits. It independently reconstructs machine pair/note identity and obligation coverage without altering the whole-book canonical scope or rebuilding signed chapters. It validates each chapter's hash-bound independent QC and signoff, receipt identity, coverage hash, fixed golden tag object, source/glossary/standard pins, and exact canonical concatenation. The manifest binds all eight receipts, tags, chapter manifests, QC, signoffs, review files, evidence and canonical files. Shared image hashes must agree. A signed aggregate cannot be silently replaced.

Local validation checks recorded remote identities against local Git objects; it does not query the network. Before `translation-v1` publication, the coordinator must freshly verify all eight remote chapter tag objects and peeled commits, the fixed golden tag, and remote main, then perform the separate aggregate review/signoff/publication gate. No automated semantic certification, exhaustive witness collation or independent human certification is implied.
